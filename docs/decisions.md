## W2. 画面と、server への中継

- 決めた人：AI　レビュー：未（人のレビューは要らない。PoC が終わったときにまとめて振り返る、親の D25）
- 画面は一枚。左にテストケースの一覧（新しい順、確認の状態の印つき）、右に選んだものの詳細。詳細には、元の日本語（`instruction`）と生成されたステップを横に並べ、その下に承認・実行のボタンと、実行の結果を置く。
- ステップは「「1」のキーを押す」のように、人が読む一文にして出す。確認事項（`expect_text`）は太字にし、結果では期待と実際の値を並べる。
- 確認待ち（`pending`）のものは「実行する」を押せなくし、「承認する」を出す。server も 409 ではじくが、押す前に分かるようにする。
- `needs_review` は登録のときに AI が決める（契約に変える道がない）ので、web ではチェックボックスを読むだけで出す。
- 実行の結果は、そのテストケースの実行を新しい順に並べ、選んだものを出す。各ステップにスクショの縮小を付け、押すと大きく出す。
- 一覧は 3 秒ごとに読み直す（画面が見えているときだけ）。AI が MCP で登録したものが、開いたままの画面に出るように。デモのため。
- web は `/api` を vite の中継で server に送る。server に CORS の設定を足さずに済み、web からは同じ場所に見える。本番のための配信（`vite build` の置き場所）は、要るときに決める。
- 消す（`DELETE /testcases/{id}`）も付けた。デモで登録し直すときに要るため。押す前に確かめる。

## W1. 型の生成と関門

- 決めた人：AI　レビュー：未（人のレビューは要らない。PoC が終わったときにまとめて振り返る、親の D25）
- Vite・React・TypeScript。型は openapi-typescript で親の `openapi.yaml` から生成し（`scripts/generate-contracts.mjs`）、呼び出しは openapi-fetch で型付きにする。手で型を書かない。
- TypeScript は 5 系にした。7 系は API が変わって、openapi-typescript が動かないため。
- 関門は `npm run check`（`tsc`・vitest・prettier）。
  - 生成し直した型が、コミットしたものと同じこと。
  - テストの偽の server（`tests/fakeServer.ts`）が返すものを、親の JSON Schema（ajv、draft 2020-12）で判定する。偽物が契約からずれると、テストが落ちる。データは契約の例から作る。
  - 画面の観点（一覧・見比べ・承認・実行・結果とスクショ・失敗・runner に届かない）を、Testing Library で人の操作のとおりに確かめる。
- Python の部品は観点を pytest-bdd の Gherkin で書くが、web は vitest の日本語のテスト名で書く。TypeScript で Gherkin を動かす道具を足すほどの数がないため。
- 依存の向きの検査（import-linter に当たるもの）は置かない。ファイルが少なく、層を分けていないため。増えたら考える。
- 親の契約は、作業フォルダで隣に並べた `../qata/` から読む（ほかの部品と同じ。次の周回で直す、親の ideas.md）。
